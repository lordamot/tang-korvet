The ExtROM boot (item 3) reaches CP/M's A> prompt in simulation. Getting there took four fixes:

- Control went to the wrong request level. devices.v put it on IR7, the name the connector and the ExtROM's documents use. The ОПТС 2.0 tests bit 0 of the ВН59's request register after raising Control (korvet20.rom 04C0h-04CEh), and Erokhin's emulator patch raises request 0 for it. Control is IR0 now, the motor time-out stays IR7. platform.md has the reasoning.
- A request bit did not follow its line. pic8259.v held an edge-mode request until acknowledged. The datasheet and Emu80 clear it when the line drops, so it does that now, and the floppy motor's request became a level (the one-shot's inverted output) instead of a one-clock pulse.
- The floppy's byte reached the CPU one read late. devices.v took the ВГ93's answer on the clock fdc.v registered it, so every read returned the previous read's value. One more pipeline stage fixes it.
- The testbench's ExtROM brain overran the 1 K FIFO. It pushed the 8 KB phase-2 loader without polling for room, and the FIFO drops what it cannot take. It credits itself from the status byte now, as the firmware always did.
